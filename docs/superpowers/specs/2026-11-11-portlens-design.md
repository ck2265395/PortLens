# PortLens 产品与技术设计

## 1. 意图

PortLens 是一款仅管理当前 Windows 电脑的桌面端口诊断工具。它既要帮助开发者快速解决端口冲突，也要为本机运维人员提供足够的进程、服务、权限与审计信息。

核心体验是：快速找到监听端口或绑定端口，理解占用者及影响范围，并在明确确认后安全地停止对应服务或进程。

## 2. 目标

- 展示本机 TCP 监听端口和 UDP 已绑定端口。
- 按端口、协议、进程名、PID、服务名、路径或命令行统一搜索与模糊匹配。
- 将端口关联到进程、Windows 服务、用户及该进程占用的其他端口。
- 支持先温和关闭、失败后再由用户选择强制结束。
- 为所有停止操作提供不可跳过的确认，并记录本地操作日志。
- 在自动刷新时保持列表、选择和详情稳定，避免界面跳动。
- 默认普通权限运行，只在必要时请求以管理员权限重启。

## 3. 非目标

第一版不包含：

- 远程主机管理。
- 抓包、流量内容分析或带宽统计。
- 防火墙规则编辑。
- 普通出站连接、`ESTABLISHED`、`TIME_WAIT` 等完整连接监控。
- 云端同步、团队账户或集中审计。
- 后台 Windows 服务常驻。

## 4. 反目标

- 不把应用做成信息密集到难以用于日常开发的网络管理控制台。
- 不让整个应用长期以管理员权限运行。
- 不使用端口号作为唯一行标识，不把端口被新进程接管误判为原进程仍在运行。
- 不允许无确认的一键杀进程，也不提供“以后不再提示”。
- 不在每轮刷新时重载整张表或打断用户当前操作。

## 5. 平台与技术约束

- 目标平台：Windows，本机管理。
- 第一版支持 Windows 10 22H2、Windows 11、Windows Server 2019、2022 和 2025，仅提供 x64 版本。
- 第一版不支持 Windows 7/8、32 位 Windows 或 Windows on ARM。
- 桌面框架：Electron。
- 界面层：React + TypeScript。
- 系统访问采用分层混合方案：定义稳定的 `SystemPortProvider` 契约，第一版用 PowerShell/CIM 实现，未来可替换为 C# 本地 helper。
- React 不直接执行系统命令；系统查询、权限判断和进程/服务操作全部位于 Electron 主进程或 helper 中。
- Electron IPC 必须使用明确的白名单接口与结构化数据，不向渲染进程暴露 Node.js 或任意命令执行能力。

## 6. 已考虑的实现方案

### 方案 A：Electron 主进程直接调用 PowerShell/CIM

开发最快、构建链最简单，但执行性能、编码、超时和不同环境兼容性容易渗入业务代码。

### 方案 B：从第一版开始配套 C# helper

Windows 系统能力最稳定，但需要同时维护 Node/Electron 与 .NET 构建、签名和分发链，第一版成本较高。

### 方案 C：分层混合方案（已选择）

先通过 `SystemPortProvider` 隔离系统实现，第一版使用 PowerShell/CIM；性能或兼容性需要时替换为 C# helper，React 与 IPC 契约保持不变。该方案兼顾交付速度和后续稳定性。

## 7. 主界面

采用已选定的“均衡工作台”布局，参考仓库根目录的 `portlens-layout-preview.html`。

### 顶部工具区

- 统一搜索框：端口、协议、进程、PID、服务、路径和命令行。
- 常用筛选：协议、监听地址范围；高级筛选可进一步包含用户、服务、权限与风险状态。
- 手动刷新按钮及最近更新时间。
- 自动刷新状态与暂停入口。

### 左侧端口列表

默认列：端口、协议、进程、PID、监听地址、状态。

- TCP 显示“监听中”，UDP 显示“已绑定”，避免暗示 UDP 存在 TCP 式监听状态。
- 支持排序、筛选和自定义列。
- 默认按端口升序，减少位置变化。
- 行身份至少由协议、本地地址、端口和 PID 组成。
- 对外监听、系统进程、服务进程等使用文字或图标标识，颜色不是唯一信息载体。

### 右侧详情栏

展示：

- 端口、协议、本地监听地址。
- 进程名、PID、路径、完整命令行、启动时间和所属用户。
- 对应 Windows 服务及服务状态（若存在）。
- 同一进程关联的其他端口。
- 风险提示及停止操作的影响范围。
- 复制诊断信息、停止服务或结束进程操作。

## 8. 搜索和筛选

- 搜索采用不区分大小写的包含匹配；纯数字同时匹配端口和 PID。
- 多关键词采用 AND 语义，以空格分隔。
- 当前搜索、筛选、排序和自定义列在应用会话内保持；持久化偏好可由实现者按常规方式处理。
- 无结果状态应说明当前过滤条件，并提供清除筛选操作。

## 9. 刷新模型

- 默认每 3 秒刷新，可选 1、3、5、10 秒或暂停。
- 使用结构化快照和差异比较，只更新变化的行。
- 保持当前排序、滚动位置、选中项和详情栏。
- 用户正在操作菜单、选择文本或处理确认框时，不重排界面。
- 新端口出现时不抢夺选择或焦点；可用非阻塞提示告知新增数量。
- 选中项消失时，详情栏保留并标记“进程已结束”，直到用户切换选择。
- 端口被不同 PID 接管时视为原记录移除并新增记录。
- 最小化时降低刷新频率；若用户启用“最小化到托盘”，同样采用低频刷新。
- 停止操作后立即针对目标 PID、服务和端口做校验，不等待下一次周期刷新。

## 10. 停止流程与安全机制

所有停止操作始终弹出确认框，不允许跳过。

确认框展示：

- 将执行的动作类型。
- 进程名、PID、目标端口和命令行。
- 同一进程关联的其他端口。
- Windows 服务信息（若存在）。
- 权限需求、影响范围和风险等级。

危险按钮不获得默认焦点。高风险场景的按钮使用明确文案，例如“确认结束 node.exe（PID 18432）”。

### 10.1 温和关闭策略

- Windows 服务通过服务控制管理器请求正常停止。
- 有主窗口的 GUI 进程发送正常关闭窗口请求。
- 对无主窗口的控制台或后台进程，第一版不模拟 `Ctrl+C`、不附加控制台、不注入代码；界面说明没有可用的安全温和关闭方式，再让用户单独确认是否强制结束。
- 温和关闭后持续核验目标身份和状态；只有确认目标仍存在时才允许进入强制结束流程。

### 10.2 共享服务宿主

- 当一个 PID 承载多个 Windows 服务时，禁止直接结束宿主进程。
- 详情栏展示该 PID 承载的服务列表，只允许停止已识别、支持停止且未被安全规则禁止的具体服务。
- 同一普通进程占用多个端口时可以结束进程，但确认框必须列出全部受影响端口。

### 10.3 硬性保护

以下对象禁止结束，提权也不能绕过：

- PID 0、PID 4。
- PortLens 自身及其子进程。
- Windows 标记为关键或受保护的进程。
- 核心登录与会话进程，包括 `smss.exe`、`csrss.exe`、`wininit.exe`、`winlogon.exe` 和 `lsass.exe`。
- 承载多个系统服务的共享宿主进程；只能按上一节规则停止具体服务。
- 执行前无法重新核验身份，或 PID 已被复用的目标。

硬性保护不能只依据进程名判断。执行操作前必须重新核验 PID、可执行文件路径、启动时间、服务映射和系统关键标记。其他高权限进程可在按需提权和强化确认后操作。

执行顺序：

1. 对 Windows 服务优先请求正常停止服务；对普通进程尝试温和关闭。
2. 短暂等待并持续验证服务、PID和端口状态，界面显示“正在关闭”。
3. 成功后更新列表并记录日志。
4. 失败或超时后，展示失败原因，并提供单独的“强制结束”选择。
5. 强制结束再次明确影响，不复用第一次确认作为隐式授权。

系统关键进程、其他用户进程或无法安全操作的对象必须明确阻止或要求提权，不应仅依靠通用错误提示。

## 11. 权限模型

- 默认以普通用户权限启动和查看可获取的信息。
- 只有在操作受保护进程、其他用户的进程或系统服务时，提示以管理员权限重新启动 PortLens。
- 提权重启前保留当前搜索、筛选和目标上下文；重启后要求用户重新确认停止操作，不能自动执行原危险操作。
- 应清晰区分“权限不足”“进程已退出”“PID 已复用”和“系统拒绝操作”。

## 12. 操作日志

本地记录以下字段：时间、动作、端口、协议、进程名、PID、服务名、执行方式、权限级别、结果与错误摘要。

- 默认保留 7 天，超期自动清理。
- 支持立即清空。
- 支持导出 JSON 和 CSV。
- 不做云同步。
- 命令行可记录，但导出前提示其中可能包含敏感参数；不主动记录完整环境变量。

## 13. 窗口和托盘行为

- 点击关闭按钮直接退出应用，并停止所有轮询。
- 普通最小化默认进入任务栏。
- 设置中可选“最小化到系统托盘”，默认关闭；即使启用，关闭按钮仍直接退出。
- 默认不随 Windows 自动启动，可在设置中主动开启。
- 若关闭时停止操作仍在执行，不立即退出。弹窗提供“继续等待”和“取消退出”，不提供立即退出。
- 操作完成后可继续执行原退出意图；若系统调用达到实现定义的安全超时，则记录“结果未知”并允许用户退出。

## 14. 状态与错误反馈

- 初次加载、刷新失败、权限不足、无结果和进程已结束均有独立状态。
- 周期刷新失败不清空现有数据；保留最后成功快照并显示其时间。
- 错误信息面向用户解释结果，同时保留可复制的技术详情用于排查。
- 结束成功、失败和需要强制处理均提供明确且不会自动消失过快的反馈。

## 15. 留给实现者的常规选择

以下内容可在实施计划中按生态成熟度决定，不需要再次确认产品意图：

- React 状态管理、路由和样式方案。
- 测试框架与目录组织。
- 本地设置和日志文件的具体存储库。
- Electron 打包工具、自动更新是否暂缓到后续版本。
- PowerShell/CIM 命令的具体组合、超时数值及数据规范化细节，但必须满足本文定义的行为与安全边界。
