# PortLens 运行与验收记录

## 数据采集

PortLens 使用 PowerShell/CIM 查询：

- `Get-NetTCPConnection -State Listen`
- `Get-NetUDPEndpoint`
- `Win32_Process`、`Win32_Service`

周期刷新采用 single-flight：前一轮系统查询未结束时不会重叠启动新查询。失败时保留上次成功结果并显示错误，不清空当前列表。部分系统进程在普通权限下可能无法读取路径、命令行或用户，界面以“不可用”呈现。

## 权限与停止行为

- 应用默认以普通用户运行。
- Windows 服务优先使用服务控制语义；有主窗口的进程尝试正常关闭。
- 无安全温和关闭路径时，必须再次确认才允许强制结束。
- PID 0/4、核心会话进程、PortLens 自身和共享服务宿主不能直接结束。
- 运行中的停止操作会阻止窗口立即退出，用户可继续等待或取消退出。

- 真实 Windows 数据查询成功，返回 TCP/UDP、PID、进程、用户、命令行和服务映射。
- 打包后的 `PortLens.exe` 成功启动。
- 最终自动化 Windows 烟测成功采集 122 个本机端口记录（64 TCP、58 UDP）；数量会随本机状态变化。
- 搜索框、端口表格、右侧详情栏、设置入口和停止按钮均在打包应用中可访问。
- 实际详情验证包含 `wslrelay.exe`、PID、用户、路径、命令行和 TCP 端口 22。
- 端口 `6379` 精确搜索和 `redis` 名称模糊搜索通过；停止按钮仅打开冻结目标的确认框，未执行操作。
- 确定性 Electron E2E 覆盖搜索、UDP 筛选、关联端口、停止确认、设置、操作日志和 820px 窄屏布局。
- `scripts/windows-smoke.ps1` 校验 TCP/UDP 数据、身份字段、安装器、打包应用启动和正常退出。
- 未对用户现有进程执行真实停止操作；停止链路由自动化测试覆盖。
